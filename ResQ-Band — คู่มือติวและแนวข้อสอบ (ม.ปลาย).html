ระบบ ResQ-Band ทำงานอย่างไร

สรุปหลักการทำงานทั้งหมดของระบบติดตามผู้ประสบภัยใต้ซากอาคาร แบ่งเป็น 10 หน่วยการเรียน แต่ละหน่วยมีเนื้อหาละเอียด จุดที่มักออกสอบ และตัวอย่างข้อสอบพร้อมเฉลย (กดที่คำถามเพื่อดูเฉลย)

สารบัญหน่วยการเรียน

1ภาพรวมระบบและปัญหาที่แก้ 2คลื่นวิทยุและ LoRa 3การแบ่งเวลา TDMA 4อุปกรณ์ 4 ชนิดและบทบาท 5ไมโครคอนโทรลเลอร์ ESP32 6เซนเซอร์วัดชีพจร MAX30102 7โปรโตคอลและการตรวจสอบข้อผิดพลาด 8การคัดแยกผู้ป่วย (Triage) 9การระบุตำแหน่งจาก RSSI 10การไหลของข้อมูลและซอฟต์แวร์

น้ำหนักข้อสอบ (แนะนำ)

หน่วย 1
ภาพรวมระบบและปัญหาที่แก้

ระบบนี้ถูกสร้างเพื่อ ค้นหาและช่วยผู้รอดชีวิตที่ติดอยู่ใต้ซากอาคารถล่ม ให้เร็วขึ้น

เนื้อหา

USAR (Urban Search and Rescue) คือภารกิจค้นหาและกู้ภัยในเขตเมือง เช่น ตึกถล่ม แผ่นดินไหว ปัญหาสำคัญคือ ผู้รอดชีวิตใต้ซากมองไม่เห็นและหาตำแหน่งยาก ขณะที่เวลามีจำกัด — โอกาสรอดจะลดลงอย่างรวดเร็วหลังผ่านไปหลายชั่วโมง (มักอ้างถึง "72 ชั่วโมงทอง")

อุปกรณ์ทั่วไปใช้ไม่ได้ในสถานการณ์นี้: GPS ใช้ใต้ซาก/ในอาคารไม่ได้เพราะสัญญาณดาวเทียมทะลุไม่ถึง และเครือข่ายมือถือ/อินเทอร์เน็ตอาจล่มเมื่อเสาสัญญาณเสียหาย ระบบ ResQ-Band จึงออกแบบให้ ทำงานได้ด้วยตัวเอง ไม่พึ่งโครงสร้างพื้นฐานภายนอก โดยใช้กำไลข้อมือส่งสัญญาณวิทยุระยะไกลของตัวเอง

ภาพรวมมี 4 ส่วน: กำไล (ผู้ประสบภัยสวม) ส่งสัญญาณ → เสารับสัญญาณ รอบพื้นที่ช่วยระบุตำแหน่ง → ศูนย์ควบคุม ประมวลผลและจัดลำดับ → เครื่องพกพา ให้เจ้าหน้าที่นำทางเข้าหา

🎯 จุดที่มักออกสอบ
  • ทำไมจึงใช้วิทยุของตัวเองแทน GPS หรือมือถือ
  • ความหมายของ USAR และ "ช่วงเวลาทอง"
  • 4 ส่วนของระบบและลำดับการทำงานคร่าว ๆ
เพราะเหตุใดระบบจึงไม่ใช้ GPS ในการระบุตำแหน่งผู้ประสบภัยใต้ซาก?อัตนัย
แนวคำตอบ: เพราะสัญญาณ GPS จากดาวเทียมทะลุผ่านคอนกรีตและซากอาคารเข้าไปใต้ดินไม่ได้ ทำให้เครื่องรับ GPS ใต้ซากไม่สามารถระบุตำแหน่งได้ ระบบจึงหันมาใช้ความแรงสัญญาณวิทยุจากเสาหลายต้นประเมินตำแหน่งแทน
ระบบ ResQ-Band ประกอบด้วยอุปกรณ์กี่กลุ่ม อะไรบ้างเติมคำ
เฉลย: 4 กลุ่ม — (1) กำไลข้อมือ Band-Node (2) เสาสัญญาณ ResQ-Pin (3) เครื่องพกพากู้ภัย ResQ-Node (4) ศูนย์ควบคุม MainNode

หน่วย 2
คลื่นวิทยุและ LoRa

หัวใจการสื่อสารของระบบคือคลื่นวิทยุ LoRa ความถี่ 433 MHz ที่ส่งได้ไกลและทะลุสิ่งกีดขวางได้ดี

เนื้อหา

คลื่นวิทยุ เป็นคลื่นแม่เหล็กไฟฟ้าชนิดหนึ่ง เดินทางในอากาศด้วยความเร็วแสง มีคุณสมบัติสำคัญคือ ความถี่ (จำนวนรอบต่อวินาที หน่วยเฮิรตซ์ Hz) โดยทั่วไป ความถี่ยิ่งต่ำ ยิ่งทะลุสิ่งกีดขวางและเลี้ยวเบนได้ดี และเดินทางได้ไกล ส่วนความถี่สูงจะถูกดูดซับง่ายกว่า

LoRa (ย่อจาก Long Range) เป็นเทคนิคการส่งวิทยุระยะไกลที่ใช้พลังงานต่ำ ระบบนี้ใช้ความถี่ 433 MHz ซึ่ง ต่ำกว่า Wi-Fi และ Bluetooth (2.4 GHz) มาก จึงทะลุคอนกรีตและซากอาคารได้ดีกว่า เหมาะกับการหาคนใต้ซาก และไปได้ไกลเป็นสิบ ๆ เมตรถึงกิโลเมตรในที่โล่ง

ค่าตั้งค่าที่สำคัญของ LoRa มีการแลกเปลี่ยน (trade-off) ระหว่าง "ระยะทาง" กับ "ความเร็ว":

พารามิเตอร์ความหมายผล
SF (Spreading Factor)ระดับการกระจายสัญญาณ (SF7–SF12)SF สูง = ไกล/ทนสัญญาณรบกวนมากขึ้น แต่ช้าลง
BW (Bandwidth)ความกว้างช่องสัญญาณ (125 kHz)แคบ = ไกลขึ้น · กว้าง = เร็วขึ้น
CR (Coding Rate)สัดส่วนบิตตรวจแก้ข้อผิดพลาด (4/5)มากขึ้น = ทนพลาดดีขึ้น แต่ข้อมูลจริงน้อยลง
RSSIความแรงสัญญาณที่รับได้ (dBm ค่าติดลบ)ยิ่งใกล้ 0 = ยิ่งแรง = อยู่ใกล้

RSSI (Received Signal Strength Indicator) เป็นตัวเลขบอกว่าเครื่องรับได้สัญญาณแรงแค่ไหน มีหน่วย dBm เป็นค่าติดลบ เช่น −40 dBm แรงกว่า −90 dBm ค่านี้สำคัญมากเพราะระบบใช้มัน ประเมินว่าผู้ประสบภัยอยู่ใกล้เสาต้นไหน

🎯 จุดที่มักออกสอบ
  • ทำไม 433 MHz ทะลุซากได้ดีกว่า 2.4 GHz (ความถี่ต่ำ = ทะลุดี)
  • ความหมายของ SF, BW, CR และผลต่อระยะ/ความเร็ว
  • RSSI คืออะไร ค่าติดลบมากหรือน้อยแปลว่าอยู่ใกล้/ไกล
ค่า RSSI = −45 dBm กับ −85 dBm ค่าใดแสดงว่าอยู่ใกล้เสามากกว่า เพราะอะไรปรนัย/อธิบาย
เฉลย: −45 dBm อยู่ใกล้กว่า เพราะ RSSI เป็นค่าติดลบ ยิ่งเข้าใกล้ 0 (ติดลบน้อย) แปลว่าสัญญาณยิ่งแรง = แหล่งกำเนิดอยู่ใกล้
เหตุใดระบบจึงเลือกความถี่ 433 MHz แทน 2.4 GHz แบบ Wi-Fiอัตนัย
แนวคำตอบ: เพราะ 433 MHz เป็นความถี่ต่ำกว่า จึงทะลุคอนกรีต/ซากอาคารและเลี้ยวเบนผ่านสิ่งกีดขวางได้ดีกว่า และเดินทางได้ไกลกว่า เหมาะกับการค้นหาผู้รอดใต้ซาก ส่วน 2.4 GHz ถูกวัสดุดูดซับง่ายทำให้ระยะสั้น

หน่วย 3
การแบ่งเวลา TDMA

มีอุปกรณ์หลายตัวแต่มีช่องวิทยุเดียว จึงต้อง "ผลัดกันส่ง" ด้วยการแบ่งเวลาแบบ TDMA

เนื้อหา

ทุกอุปกรณ์ในระบบใช้ ช่องความถี่วิทยุเดียวกัน (433 MHz) ถ้าปล่อยให้ส่งพร้อมกัน สัญญาณจะ ชนกัน (collision) และเสียหายทั้งคู่ เปรียบเหมือนคนหลายคนพูดพร้อมกันในห้องเดียว จะฟังไม่รู้เรื่อง

TDMA (Time Division Multiple Access — การเข้าถึงหลายทางด้วยการแบ่งเวลา) แก้ปัญหานี้โดย แบ่งเวลาออกเป็นช่วงย่อย (slot) แล้วกำหนดให้แต่ละอุปกรณ์ส่งเฉพาะช่องเวลาของตัวเอง เหมือนการผลัดกันพูดทีละคน

ระบบใช้รอบเวลา 10 วินาที แบ่งเป็น 10 ช่อง ช่องละ 1 วินาที โดยศูนย์ควบคุมจะส่งสัญญาณ BEACON ในช่องแรกเพื่อ จับเวลาให้ทุกอุปกรณ์ตรงกัน (synchronization) เหมือนสัญญาณนกหวีดบอกให้เริ่มนับเวลาพร้อมกัน

ช่องผู้ส่งส่งอะไร
0ศูนย์ควบคุมBEACON — จับเวลา + คำสั่ง
1–2กำไลชีพจร + สถานะ (HEARTBEAT)
3–6เสา ×4รายงาน RSSI ที่ได้ยิน
7ศูนย์ควบคุมคำสั่งภารกิจ
8เครื่องกู้ภัยยืนยันภารกิจ
9สำรองช่องฉุกเฉินสำรอง
🎯 จุดที่มักออกสอบ
  • ปัญหาที่ TDMA แก้คืออะไร (การชนกันของสัญญาณ)
  • หน้าที่ของ BEACON (จับเวลาให้ตรงกัน)
  • คำนวณ: 1 รอบมีกี่วินาที กี่ช่อง ช่องละกี่วินาที
ถ้าอุปกรณ์ทุกตัวส่งสัญญาณพร้อมกันบนความถี่เดียว จะเกิดปัญหาอะไร และ TDMA แก้อย่างไรอัตนัย
แนวคำตอบ: สัญญาณจะชนกัน (collision) ทำให้ข้อมูลเสียหายรับไม่ได้ TDMA แก้โดยแบ่งเวลาเป็นช่อง แล้วให้แต่ละอุปกรณ์ส่งเฉพาะช่องเวลาของตน จึงไม่ทับกัน โดยมี BEACON คอยจับเวลาให้ทุกตัวตรงกัน
รอบ TDMA ยาว 10 วินาที แบ่งเป็น 10 ช่อง แต่ละช่องยาวเท่าใด และเสาสัญญาณใช้ช่องใดบ้างคำนวณ/เติมคำ
เฉลย: ช่องละ 10÷10 = 1 วินาที · เสาสัญญาณ (4 ต้น) ใช้ช่องที่ 3–6

แต่ละอุปกรณ์มีหน้าที่เฉพาะ ทำงานร่วมกันเป็นระบบ
อุปกรณ์ใครใช้/อยู่ที่ไหนหน้าที่หลัก
Band-Node
กำไลข้อมือ		ผู้ประสบภัยสวมวัดชีพจร แล้วส่งสัญญาณบอกว่า "ยังอยู่ตรงนี้"
ResQ-Pin ×4
เสาสัญญาณ		ติดตั้งรอบพื้นที่ฟังสัญญาณกำไล วัดความแรง (RSSI) รายงานศูนย์ → ใช้หาตำแหน่ง

เครื่องพกพา		เจ้าหน้าที่กู้ภัยถือรับคำสั่งเป้าหมาย + ข้อมูลผู้สวม นำทางเข้าหาด้วยความแรงสัญญาณ

🎯 จุดที่มักออกสอบ
  • จับคู่อุปกรณ์กับหน้าที่
  • อุปกรณ์ใดทำหน้าที่ "จับเวลา" ให้ทั้งระบบ (MainNode)
  • เสาสัญญาณช่วยเรื่องอะไร (ระบุตำแหน่งจาก RSSI)
อุปกรณ์ใดทำหน้าที่ประมวลผลกลางและจับเวลา TDMA ให้ทั้งระบบปรนัย
เฉลย: MainNode (ศูนย์ควบคุม) — ส่ง BEACON จับเวลา รวมข้อมูล และคำนวณลำดับความสำคัญ

หน่วย 5
ไมโครคอนโทรลเลอร์ ESP32 และการเชื่อมต่อ

"สมอง" ของทุกอุปกรณ์คือไมโครคอนโทรลเลอร์ ESP32 ซึ่งอ่านเซนเซอร์และคุมวิทยุ

เนื้อหา

ไมโครคอนโทรลเลอร์ (MCU) คือคอมพิวเตอร์ขนาดเล็กบนชิปเดียว มีหน่วยประมวลผล หน่วยความจำ และขาสัญญาณในตัว ระบบนี้ใช้ ESP32 (และรุ่น ESP32-S3 สำหรับศูนย์ควบคุม) ซึ่งมี Wi-Fi และ Bluetooth ในตัว

MCU ติดต่อกับอุปกรณ์อื่นผ่าน "ขาสัญญาณ" (GPIO) และมาตรฐานการสื่อสารหลัก 3 แบบ:

มาตรฐานใช้กับลักษณะ
I2Cเซนเซอร์ชีพจรใช้ 2 สาย (SDA=ข้อมูล, SCL=จังหวะ) ต่ออุปกรณ์หลายตัวบนสายเดียว แต่ละตัวมี "ที่อยู่" (address)
SPIโมดูลวิทยุ LoRaเร็วกว่า ใช้ 4 สาย (SCK, MISO, MOSI, CS) เหมาะกับข้อมูลปริมาณมาก
USB (Serial)ศูนย์ ↔ คอมพิวเตอร์ส่งข้อมูลเป็นข้อความ (JSON) ให้หน้าเว็บแสดงผล
🎯 จุดที่มักออกสอบ
  • MCU คืออะไร ต่างจากคอมพิวเตอร์ทั่วไปอย่างไร
  • I2C ใช้กี่สาย, SPI ใช้กี่สาย, ใช้กับอะไร
  • GPIO คืออะไร
เซนเซอร์วัดชีพจรเชื่อมต่อกับ ESP32 ด้วยมาตรฐานใด และใช้กี่สายสัญญาณปรนัย
เฉลย: ใช้ I2C จำนวน 2 สายสัญญาณ คือ SDA (สายข้อมูล) และ SCL (สายจังหวะสัญญาณนาฬิกา)

หน่วย 6
เซนเซอร์วัดชีพจร MAX30102

กำไลวัดชีพจรด้วย "แสง" ผ่านเทคนิค PPG ไม่ต้องเจาะหรือสัมผัสกระแสไฟ

เนื้อหา

MAX30102 เป็นเซนเซอร์วัดชีพจรแบบใช้แสง หลักการเรียกว่า PPG (Photoplethysmography): เซนเซอร์ยิงแสง (LED อินฟราเรด) เข้าไปที่ผิวหนัง แล้ววัดปริมาณแสงที่สะท้อนกลับ

เมื่อหัวใจเต้นแต่ละครั้ง เลือดจะไหลผ่านหลอดเลือดใต้ผิวมากขึ้น เลือดที่มากขึ้นดูดกลืนแสงมากขึ้น แสงสะท้อนกลับจึงลดลงเป็นจังหวะ เซนเซอร์นับจังหวะการเปลี่ยนแปลงนี้แล้วคำนวณเป็น อัตราการเต้นหัวใจ (Heart Rate) หน่วยครั้งต่อนาที (bpm)

ข้อควรระวังทางเทคนิค: สัญญาณ PPG หนึ่งจังหวะหัวใจมีคลื่นสะท้อนตามมาเล็ก ๆ ถ้าตั้งค่าไวเกินไป ระบบอาจ นับซ้ำ (double-count) ทำให้ค่าชีพจรสูงผิด (เช่น จริง 90 อ่านได้ ~180) จึงต้องกำหนด "ช่วงเวลาห้ามนับซ้ำ" เพื่อให้ค่าถูกต้อง

🎯 จุดที่มักออกสอบ
  • PPG วัดชีพจรด้วยหลักการอะไร (แสง/การสะท้อน)
  • ทำไมเลือดที่ไหลมากทำให้แสงสะท้อนน้อยลง
  • หน่วยของอัตราการเต้นหัวใจ (bpm)
เซนเซอร์ MAX30102 วัดชีพจรได้อย่างไร โดยไม่ต้องเจาะเลือดอัตนัย
แนวคำตอบ: ใช้หลักการ PPG คือยิงแสง (อินฟราเรด) เข้าผิวหนังแล้ววัดแสงสะท้อนกลับ ทุกครั้งที่หัวใจเต้น เลือดไหลผ่านมากขึ้นและดูดกลืนแสงมากขึ้น แสงสะท้อนจึงลดลงเป็นจังหวะ เซนเซอร์นับจังหวะนี้แล้วแปลงเป็นอัตราการเต้นหัวใจ (bpm)

หน่วย 7
โปรโตคอลและการตรวจสอบข้อผิดพลาด

ข้อมูลถูกจัดเป็น "แพ็กเก็ต" ที่มีรูปแบบตายตัว และมี CRC ตรวจว่าไม่เพี้ยนระหว่างส่ง

เนื้อหา

โปรโตคอล (Protocol) คือข้อตกลงรูปแบบการสื่อสารที่ทุกอุปกรณ์เข้าใจตรงกัน ข้อมูลจะถูกจัดเป็น แพ็กเก็ต (Packet) ซึ่งมีส่วนประกอบเช่น: รหัสเริ่มต้น (magic) · ชนิดแพ็กเก็ต · เนื้อข้อมูล (เช่น ชีพจร) · และรหัสตรวจสอบท้ายสุด

ชนิดแพ็กเก็ตหลักในระบบ เช่น BEACON (จับเวลา) · HEARTBEAT (ชีพจรจากกำไล) · PIN_SIGHTING (RSSI จากเสา) · ASSIGNMENT (สั่งกู้ภัย) · FOUND (ยืนยันพบ)

CRC (Cyclic Redundancy Check) คือค่าตรวจสอบที่คำนวณจากข้อมูลแล้วแนบไปท้ายแพ็กเก็ต ฝั่งรับจะคำนวณใหม่แล้วเทียบ ถ้าไม่ตรง แปลว่า ข้อมูลเพี้ยนระหว่างทาง (เพราะสัญญาณวิทยุมีสัญญาณรบกวน/noise) ก็จะทิ้งแพ็กเก็ตนั้น เพื่อไม่ให้ระบบใช้ข้อมูลผิด ระบบนี้ใช้ CRC ขนาด 16 บิต (CRC16)

🎯 จุดที่มักออกสอบ
  • Packet คืออะไร มีองค์ประกอบอะไรบ้าง
  • CRC มีไว้ทำอะไร ทำไมการส่งวิทยุจึงต้องมี
  • ยกตัวอย่างชนิดแพ็กเก็ตและหน้าที่
CRC ในแพ็กเก็ตมีหน้าที่อะไร และเหตุใดการสื่อสารด้วยวิทยุจึงจำเป็นต้องมีอัตนัย
แนวคำตอบ: CRC เป็นรหัสตรวจสอบความถูกต้องของข้อมูล ฝั่งรับคำนวณใหม่แล้วเทียบกับที่ส่งมา ถ้าไม่ตรงแสดงว่าข้อมูลเพี้ยน จำเป็นเพราะสัญญาณวิทยุมีสัญญาณรบกวน (noise) ทำให้บิตข้อมูลผิดพลาดได้ CRC ช่วยให้ระบบทิ้งข้อมูลที่ผิดแทนที่จะนำไปใช้

หน่วย 8
การคัดแยกผู้ป่วย (Triage) และคะแนนความสำคัญ

เมื่อเจอผู้รอดหลายคนแต่กู้ภัยมีจำกัด ต้องตัดสินใจว่า ช่วยใครก่อน ด้วยระบบให้คะแนน

เนื้อหา

Triage คือการคัดแยกผู้ป่วยตามความรุนแรงเพื่อจัดลำดับการช่วยเหลือ นิยมใช้รหัสสี: เขียว = ปลอดภัย, เหลือง = เฝ้าระวัง, แดง = วิกฤต, ดำ = เสียชีวิต

ศูนย์ควบคุมให้ คะแนนความเร่งด่วน แก่ผู้ประสบภัยแต่ละคนแล้วส่งกู้ภัยไปหาคนคะแนนสูงสุดก่อน เกณฑ์คะแนนจริงในระบบ:

ปัจจัยเงื่อนไขคะแนน
ชีพจรผิดปกติวิกฤต (<40 หรือ >150 ครั้ง/นาที) / เฝ้าระวัง+100 / +30
เงียบหายไม่ส่งสัญญาณ (ต่อ 1 นาที, สูงสุด +200)+20 / นาที
ผู้ควบคุมสั่งเร่งกดปุ่มเพิ่มความสำคัญ (Boost)+500
🎯 จุดที่มักออกสอบ
  • Triage คืออะไร รหัสสีแต่ละสีหมายถึงอะไร
  • ทำไมต้องจัดลำดับ (ทรัพยากรจำกัด)
  • คำนวณคะแนนรวมจากเงื่อนไขที่กำหนด
ผู้ประสบภัย A ชีพจร 170 (วิกฤต) และเงียบหายไป 2 นาที ส่วน B ชีพจรปกติแต่ถูกกด Boost ใครควรถูกช่วยก่อนวิเคราะห์/คำนวณ
เฉลย: A ได้ 100 (ชีพจรวิกฤต) + 40 (เงียบ 2 นาที × 20) = 140 · B ได้ 500 (Boost) = 500 → ควรช่วย B ก่อน เพราะผู้ควบคุมสั่งเร่งด้วยตนเอง (คะแนนสูงกว่า) — ข้อนี้สอนว่าคำสั่งมนุษย์มีน้ำหนักเหนือคะแนนอัตโนมัติ

หน่วย 9
การระบุตำแหน่งจาก RSSI

ระบบไม่ใช้ GPS แต่ประเมินตำแหน่งจาก ความแรงสัญญาณ (RSSI) ที่เสาหลายต้นได้ยิน

เนื้อหา

หลักการพื้นฐาน: ยิ่งกำไลอยู่ใกล้เสาต้นใด เสานั้นจะได้ยินสัญญาณแรง (RSSI สูง) ถ้ามีเสาเพียงต้นเดียว จะรู้แค่ว่าอยู่ "ใกล้ต้นนั้น" แต่ไม่รู้ทิศ

เมื่อใช้ เสาหลายต้น (ในระบบมี 4 ต้น) เรารู้ RSSI จากทุกต้น แล้วนำมา ถ่วงน้ำหนัก (weighted centroid): เสาที่ได้ยินแรงกว่ามีน้ำหนักมากกว่า ตำแหน่งประมาณจึงถูกดึงเข้าหาเสาที่แรงที่สุด แต่ยังอยู่ "ระหว่าง" เสาต่าง ๆ ตามสัดส่วน — แนวคิดนี้คล้าย trilateration (การหาตำแหน่งจากระยะถึงจุดอ้างอิงหลายจุด)

ในระยะสุดท้าย (last-meter) เจ้าหน้าที่กู้ภัยใช้หลักการเดียวกันแบบ "ร้อน/เย็น": เดินไปทางที่สัญญาณแรงขึ้น (ร้อน) = เข้าใกล้ เดินผิดทางสัญญาณอ่อนลง (เย็น) = ห่างออก

🎯 จุดที่มักออกสอบ
  • ทำไมเสา 1 ต้นไม่พอ ต้องใช้หลายต้น
  • weighted centroid / trilateration ทำงานอย่างไรเบื้องต้น
  • การนำทาง "ร้อน/เย็น" หมายถึงอะไร
เพราะเหตุใดการใช้เสาสัญญาณเพียงต้นเดียวจึงระบุตำแหน่งได้ไม่แม่นยำอัตนัย
แนวคำตอบ: เสา 1 ต้นบอกได้แค่ว่า "อยู่ใกล้หรือไกล" จากความแรงสัญญาณ แต่ไม่บอกทิศทาง ผู้ประสบภัยจึงอาจอยู่รอบเสาเป็นวงกลมทิศไหนก็ได้ ต้องใช้หลายต้นแล้วเทียบความแรงเพื่อ "ตีกรอบ" ตำแหน่งให้แคบลง (trilateration)

หน่วย 10
การไหลของข้อมูลและซอฟต์แวร์

ข้อมูลไหลจากกำไล → เสา/ศูนย์ → คอมพิวเตอร์ → กลับไปเครื่องกู้ภัย เป็นวงจรครบ

เนื้อหา — เส้นทางข้อมูล (สรุปเป็นขั้น)

  1. กำไล วัดชีพจร → ส่งสัญญาณ HEARTBEAT ทาง LoRa ตามช่อง TDMA
  2. เสา 4 ต้น ได้ยินสัญญาณ → วัด RSSI → รายงานให้ศูนย์
  3. ศูนย์ควบคุม รวมชีพจร + RSSI → คิดคะแนน Triage + ประเมินตำแหน่ง → ส่งข้อมูลผ่านสาย USB ให้คอมพิวเตอร์
  4. หน้าเว็บศูนย์สั่งการ (บนคอมพิวเตอร์) แสดงแผนที่ ตำแหน่ง คิวลำดับความสำคัญ ให้ผู้ควบคุมตัดสินใจ
  5. ผู้ควบคุมสั่งช่วยเหลือ → ศูนย์ส่งคำสั่ง (ASSIGNMENT) พร้อมข้อมูลผู้สวมทาง LoRa ให้ เครื่องกู้ภัย
  6. เครื่องกู้ภัย แสดงเป้าหมาย+ข้อมูลบนหน้าจอของตัวเอง → นำทางเข้าหา → กดยืนยันเมื่อพบ (FOUND)

ส่วนซอฟต์แวร์: คอมพิวเตอร์เชื่อมกับศูนย์ผ่าน USB (Web Serial) รับข้อมูลเป็นข้อความ แล้วหน้าเว็บนำมาวาดบน แผนที่ ส่วนเครื่องกู้ภัยมีหน้าเว็บของตัวเอง (ผ่าน Wi-Fi ในตัว) เพื่อทำงานได้แม้ไม่มีอินเทอร์เน็ต

🎯 จุดที่มักออกสอบ
  • เรียงลำดับเส้นทางข้อมูลจากกำไลจนถึงเครื่องกู้ภัย
  • ศูนย์เชื่อมกับคอมพิวเตอร์ด้วยอะไร (USB)
  • ทำไมเครื่องกู้ภัยต้องมีหน้าเว็บของตัวเอง (ทำงานแบบออฟไลน์)
จงเรียงลำดับการไหลของข้อมูลตั้งแต่กำไลวัดชีพจร จนเจ้าหน้าที่ได้รับคำสั่งภารกิจเรียงลำดับ
เฉลย: กำไลส่ง HEARTBEAT → เส ารับ+วัด RSSI รายงานศูนย์ → ศูนย์รวมข้อมูล คิดคะแนน+ตำแหน่ง → ส่งผ่าน USB ให้เว็บแสดงแผนที่ → ผู้ควบคุมสั่งช่วย → ศูนย์ส่ง ASSIGNMENT ทาง LoRa → เครื่องกู้ภัยรับและนำทาง

อภิธานศัพท์สำคัญ (ทบทวนก่อนสอบ)

คำศัพท์ความหมายสั้น ๆ

LoRaเทคนิควิทยุระยะไกล พลังงานต่ำ (ระบบใช้ 433 MHz)
RSSIความแรงสัญญาณที่รับได้ (dBm ค่าติดลบ ยิ่งใกล้ 0 ยิ่งแรง)
TDMAการแบ่งเวลาให้อุปกรณ์ผลัดกันส่ง ป้องกันสัญญาณชนกัน
BEACONสัญญาณจากศูนย์ที่ใช้จับเวลาให้ทุกอุปกรณ์ตรงกัน
MCUไมโครคอนโทรลเลอร์ — คอมพิวเตอร์เล็กบนชิป (ระบบใช้ ESP32)
I2C / SPIมาตรฐานเชื่อมเซนเซอร์ (I2C 2 สาย) / โมดูลวิทยุ (SPI 4 สาย)
PPGการวัดชีพจรด้วยแสงและการสะท้อน (เซนเซอร์ MAX30102)
